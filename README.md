# Аквадом — водоподготовка для частного дома

Одностраничный сайт для Приморского края. HTML, CSS, JavaScript; без серверной части и зависимостей в браузере. Цены относятся к оборудованию, монтаж рассчитывается отдельно.

## Локальный просмотр

Требуется Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Адрес: http://127.0.0.1:4173. Остановить сервер: Ctrl+C.

```sh
npm run build
npm test
```

Готовый сайт находится в `dist/`. Тесты запускают установленный Google Chrome на Windows. На других системах перед первым запуском выполните `npx playwright install chromium`. Для другого пути Chrome задайте переменную `CHROME_PATH`.

## Где редактировать

- `content.js` — шесть направлений, описания, цены оборудования, вопросы и ответы.
- `forms-config.js` — общая CRM-форма и формы шести направлений.
- `index.html` — структура, основные тексты и ссылки.
- `styles.css` — оформление и адаптация.
- Шрифт PT Sans (обычное и жирное начертания) хранится в `assets/fonts/` и загружается с самого сайта без обращения к Google Fonts. Лицензия SIL Open Font License находится рядом в `OFL.txt`. Основной текст — 18 px, меню и кнопки — 16 px.
- `assets/` — предоставленный логотип и собственные SVG-иллюстрации оборудования. Иллюстрации условные: они не определяют состав комплекта и не являются фотографиями выполненных работ.

Названия, описания и цены основаны на предоставленном документе. Полный состав оборудования и рабочие показатели не публикуются. Фотографии работ, отзывы, сроки и гарантии не выдумываются.

## Подключение Битрикс24

Общая форма `general` подключена к CRM Аквадом: `inline/3/jjh64m`. Она размещена в двух блоках страницы и в окне общего подбора. Её полями, согласием, оформлением и отправкой управляет Битрикс24. Прямая ссылка пока не предоставлена: до её добавления вместо резервной ссылки показывается подсказка обновить страницу.

Шесть направлений пока имеют значение `null` и остаются демонстрационными. Такие формы не отправляют данные, не используют localStorage/cookies и не показывают успешную отправку. Кнопки отправки отключены. Введённые в демонстрационное окно данные удаляются при его закрытии. Загруженная CRM-форма сохраняется при закрытии общего окна, чтобы повторное открытие не создавало дубликат и не сбрасывало ввод.

Для каждого направления возьмите из Битрикс24 официальный код размещения **«На странице сайта»** и прямую ссылку на форму. Пример заполнения (значения условные):

```js
general: {
  id: '123',
  code: 'abcdef',
  loaderUrl: 'https://ваш-домен-Битрикс24/путь/loader_123.js',
  url: 'https://ваша-прямая-ссылка-на-форму/'
}
```

`id` и `code` берутся из `data-b24-form="inline/123/abcdef"`, а `loaderUrl` — из URL загрузчика официального кода. Используйте реальные HTTPS-адреса из Битрикс24. Не добавляйте вебхуки, пароли или API-токены в клиентский код.

Ключи: `general`, `uv`, `clarity`, `sorption`, `iron`, `softening`, `complex`. Общая форма отображается в двух блоках страницы и по общим кнопкам. В Битрикс24 настройте повторное размещение и проверьте каждую точку входа. Для направлений задайте отдельные формы со скрытым полем типа системы; оно должно попадать в CRM.

Цвета и согласие на обработку данных настраиваются в редакторе Битрикс24. Внешние формы загружаются официальным скриптом; если в конфигурации задан `url`, ссылка на отдельную форму доступна как резервный путь. Результат отправки показывает Битрикс24. Загрузка и отправка — отдельные проверки: создание реальной заявки нужно подтвердить в CRM.

Проверка после подключения: общая форма во всех размещениях; каждое из шести направлений; повторное открытие окна; обязательные поля; согласие; отправка; появление заявки и верного направления в CRM; резервная ссылка при недоступном скрипте; мобильный экран. Тестовые заявки согласовать с ответственным за CRM.

## Vercel

Репозиторий: https://github.com/dskiryanov-coder/landingwater

1. В своём аккаунте Vercel откройте **Add New → Project** (https://vercel.com/new).
2. Подключите GitHub и разрешите доступ к `dskiryanov-coder/landingwater`.
3. Импортируйте репозиторий. **Root Directory** оставьте корнем репозитория, **Framework Preset — Other**, **Production Branch — main**. Настройки берутся из `vercel.json`: команда `npm run build`, папка `dist`. Версия Node.js `22.x` указана в `package.json`. Дополнительные переменные окружения не нужны.
4. Нажмите **Deploy**. После успешной публикации Vercel выдаст HTTPS-адрес сайта. Изменения `main` будут публиковаться автоматически после подключения GitHub.
5. Откройте выданную ссылку на компьютере и телефоне без VPN через свои сети. Доступность из России необходимо проверить на конкретном адресе; смена площадки сама по себе её не гарантирует. Для показа другим людям проверьте настройки Deployment Protection: посетители не должны попадать на обязательный вход в Vercel.

На демонстрации индексация закрыта тремя способами: meta robots, `robots.txt`, HTTP-заголовок X-Robots-Tag на Vercel. Это не ограничивает доступ по ссылке: сайт предназначен для публичного просмотра. Чувствительных данных в проекте нет.

После настройки сохраните выданный Vercel адрес в описании GitHub-репозитория. Домен `aquadom.info` не переключался. Старый проект Netlify не удаляется автоматически: при необходимости остановите его автопубликации в панели Netlify после проверки нового сайта.

## Перенос и запуск для клиентов

Загрузите **содержимое** `dist/` на статический хостинг с HTTPS. Сохраните относительные пути, включая `assets/`. Серверный код, база данных и особые правила перенаправления не требуются. Папка может быть размещена в корне или в подкаталоге сайта.

Перед приёмом заявок:

- Подключить реальные CRM-формы, проверить заявку в CRM и согласие на обработку данных.
- Подтвердить контакты компании, добавить ссылки на её утверждённые документы.
- Подтвердить цены и тексты с инженером; добавить реальные фото, если они предоставлены.
- Удалить meta robots из `index.html`, изменить `robots.txt` и убрать `X-Robots-Tag` из `vercel.json`, если сайт готов к индексации.
- При подключении своего домена следовать DNS-инструкциям выбранного хостинга. Не менять действующий магазин aquadom.info без отдельного согласования адреса лендинга.

## Проверки

Playwright проверяет соответствие шести карточек и цен, правильное направление формы, закрытие окна и возврат фокуса, удержание клавиатурного фокуса, отсутствие отправки и хранения данных заглушками, мобильное меню и FAQ, отсутствие горизонтальной прокрутки на шести ширинах, резервную CRM-ссылку и запрет индексации. Снимки desktop/mobile сохраняются в `test-results/` и не коммитятся.

Автотесты блокируют обращения к реальной CRM. Демонстрационный режим проверяется на неподключённых направлениях; общая форма проверяется с имитацией официального загрузчика, включая повторное открытие и уникальные идентификаторы размещений. Успешность реальных заявок подтверждается отдельно в CRM.
